# 시점형 표적 개선 2종 사전 계획 (2026-10-04, 실행 전 고정)

> 기준선: 최종 구성(Qwen3-4B + 검색 10) 3회, 공식 채점(Opus ∧ Codex) 0.633 · 시점형 L4 15문항 중 6.3
> 근거: 공식 채점 재평가에서 검증 단계(전체 적용)가 시점형 6.3 → 10.3(유의), 기존 답변 합성 추정에서 "시행 예정 개정 질문에만 적용" 0.650·시점형 9.7(유의)
> 결과는 `docs/findings/`에 별도 기록, 이 문서는 결과 확인 후 수정 금지

## 공통

- 대상 질문: 근거 블록 중 하나라도 시행 상태가 "개정 예정 있음" 또는 "아직 시행 전"인 질문(합성 추정 기준 41문항), 그 외 질문은 기준선과 같은 경로
- 각 3회 실행(`--no-cache --no-judge`, Luna 채점은 공식 채점에서 제외됐으므로 생략) → `eval.rejudge --all`로 공식 채점
- 판정: 기준선 3회와 문항별 3회 평균 paired bootstrap, 전체 정답률과 시점형 L4 부분집합, 대상 외 질문의 변화(기대 0, 실행 간 흔들림만)
- 예산: Luna 생성 실험 1 상한 3,000원 · 실험 2 상한 2,500원(실행당 `--budget` 1,200원), 합계 5,500원 초과 시 중단

## 실험 1: 조건부 검증 단계 (`--verify-pending`)

- 변경: 대상 질문에서만 1차 답변 뒤 검증 호출(근거와 대조해 누락·근거 없는 문장 수정), 그 외 질문은 1차 답변 그대로
- 예측: 전체 0.633 → 0.645~0.660(전체 유의는 어려움), 시점형 6.3 → 9~10(유의), 대상 외 질문 변화 노이즈 내, 비용 기준선 대비 약 1.3배
- 실패 기준: 시점형 개선이 CI 하한 0 이하 → 합성 추정(9.7)이 실측에서 재현되지 않음으로 보고

## 실험 2: 시점형 답변 규칙 (`--temporal-rule`)

- 변경: 대상 질문에서만 생성 지시문에 시점 규칙 추가 + 시행 예정 개정의 바뀌는 항·호 표시(`pending_detail`과 같은 내용) — 추가 호출 없음
  - 규칙: 기준일 현재 시행 중인 내용 → 개정으로 바뀌는 내용 → 공포일·시행일 → 기준일 현재 적용 여부 순서, 결론이 개정 전후로 달라지면 둘 다 밝힘
- 예측: 시점형 6.3 → 8~10(유의 가능), 전체 노이즈 내~소폭 상승, 비용 기준선과 비슷
- 비교 의미: 실험 1과 비슷한 시점형 개선이면 검증 호출 없이 프롬프트만으로 해결(더 싼 해법), 못 미치면 2차 검증의 효과가 지시보다 큼

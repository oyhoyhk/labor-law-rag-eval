# 과적합 vs 일반화 실험 결과

> 사전 등록: `docs/plans/2026-10-03-overfit-vs-generalize-preregistration.md` · 결과: `eval/results/v2/{v2-fewshot-dev,v2-hybrid,final-noise-*}` · 비용 1,892원(노이즈 2회 867 + 실험 2개 1,025, 상한 2,000)

## 결론

- **과적합(dev 예시 재사용)**: 전체 완전 정답 0.768 → 0.826 **유의 "개선"** — 분할 없이 보면 진짜 개선으로 오판. dev/test로 나누면 정답 포인트 dev +0.066(유의) vs test +0.022(노이즈 내) → 일반화 격차 약 3배, 평가셋 누수의 전형
- **일반화 후보(하이브리드 검색)**: 예측 실패 — dev·test 모두 개선 없음, 인용 정밀도 유의 악화, test 답변 품질 소폭 하락(노이즈 내). dev 조정 단계에서 이미 dev 이득이 없었으므로 "dev 기준 미채택"이 올바른 결정
- **평가 방법 결함 발견·수정**: 단일 기준선 실행과 비교하면, 기준선에서 우연히 틀렸던 흔들림 문항(n19·n24·n25)이 어떤 실험에서든 "개선"으로 잡힘(평균 회귀) → 두 실험 모두 dev에서 가짜 유의 개선 → 기준선을 3회 문항별 평균으로 바꾸는 `compare diff --base-runs` 추가

## 예측 대비

| 방법 | 예측 | 결과 |
|---|---|---|
| ① 과적합 | dev 유의 상승, test 노이즈 내 | **적중** (정답 포인트 기준), 완전 정답은 dev 상승폭이 노이즈 폭과 같아 경계 |
| ② 하이브리드 | dev·test 함께 상승 | **실패** — 상승 없음, 인용 정밀도 악화 |

## 분석

### ① 과적합
- dev 40문항 전부 자기 문항의 참고 답안을 예시 1번으로 열람 → 정답 포인트·인용 형식을 그대로 따라 씀(인용 정밀도 dev +0.123)
- test는 이웃 dev 예시만 열람 → 정답 포인트 +0.022, 정상 few-shot 수준의 작은 효과
- 전체 완전 정답 "유의 개선"은 dev 누수가 만든 착시 → **평가셋을 프롬프트·예시에 재사용하면 집계 점수만으로는 탐지 불가, dev/test 분할 비교가 필수**인 근거
- dev 완전 정답 상승이 정답 포인트만큼 크지 않은 이유: dev 기준선 실패 문항 중 상당수가 검색 실패(Recall 불변) → 예시를 봐도 근거 블록에 없는 내용은 프롬프트 규칙상 쓰지 못함

### ② 하이브리드
- 문자 2-gram BM25가 조 전체 문서에서 흔한 법률 용어(근로자·사용자·임금)에 반응 → 상위권에 일반 조문 유입, dev 조정 단계(LLM 없음)에서 이미 dense 단독보다 낮음(Recall all 0.675 → 0.650)
- test 검색은 소폭 상승(0.712 → 0.750)했으나 답변 품질은 오히려 하락 → 검색 지표 개선이 답변 개선으로 이어지지 않는 사례, 검색 지표만으로 채택 판단 불가
- 다음: 형태소 분석 기반 BM25, 키워드 검색은 법령명·조문 번호 직접 언급 질의에만 적용

### 평가 방법 개선: 단일 기준선의 평균 회귀
- 단일 실행 기준선 대비: 과적합 dev +0.125, 하이브리드 dev +0.100 — 둘 다 "유의 개선"
- 상승 문항 대부분(n19·n24·n25·g018)이 기준선 3회 중에서도 결과가 바뀌는 문항 → 기준선 1회에서 마침 틀렸던 문항이 실험에서 맞은 것
- 수정: 기준선 3회의 문항별 평균과 비교(`--base-runs`), 결과 하이브리드 dev 가짜 개선 소멸, 과적합 dev 완전 정답도 경계로 축소
- 이후 모든 비교는 다회 기준선 사용을 원칙으로 함(노이즈 측정 런을 그대로 재사용하므로 추가 비용 없음)

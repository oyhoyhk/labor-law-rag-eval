# 노동법령 RAG QA + 자체 Eval Harness

노동 관계 법령 24건, 대법원 판례 400건 기반 Citation RAG 서비스와 품질 평가 체계 - **공식 전체 정답률 기준선 0.470 → 최종 0.633 (+16.3%p, 95% CI +8.7~+24.0)**

> 상세 리포트: [Part A](docs/reports/part-a-rag-service.md), [Part B](docs/reports/part-b-eval-harness.md), [Part C](docs/reports/part-c-experiments.md), 실측 기록 [docs/findings/](docs/findings/), 사전 등록 [docs/plans/](docs/plans/)

## 실행 방법

```bash
# 1. 설치 (Python 3.12+, uv, 메모리 16GB 이상 권장)
uv sync
cp .env.example .env

# 2. Corpus 수집 (선택 - 원문 스냅샷이 data/raw/에 포함됨)
uv run python scripts/fetch_laws.py
uv run python scripts/fetch_precedents.py bulk --max 400

# 3. 인제스트 (LLM 없음, 첫 실행 시 임베딩 모델 내려받기) + 테스트
make ingest
uv run pytest -q

# 4. 서버 실행
uv run uvicorn app.api:app --port 8000
curl localhost:8000/v1/query -H 'Content-Type: application/json' \
  -d '{"question": "연차휴가를 시간 단위로 쓸 수 있나요?", "as_of": "2026-10-01"}'   # "stream": true → SSE

# 5. 평가 (Gold Set 100문항 → runs/<시각>_<이름>/report.md)
make eval NAME=final                                                    # 생성 + 결정적 지표
uv run python -m eval.rejudge final runs/<실행1> runs/<실행2> runs/<실행3> --all   # 공식 채점(Opus ∧ Codex)
uv run python -m eval.multirun '<기준선 실행들>' '<실험 실행들>'          # 3회 대 3회 비교
```

| 환경 변수 | 용도 |
|---|---|
| `ELICE_API_KEY`, `ELICE_BASE_URL`, `LLM_MODEL` | 엘리스 ML API (`https://mlapi.run/v1`, `openai/gpt-5.6-luna`) |
| `LAW_OC` | 국가법령정보 OPEN API 인증키 (수집 시에만) |

- 공식 채점: 로컬 `claude`, `codex` CLI 로그인 필요, 채점마다 캐시 저장, 한도 초과 시 이어서 실행
- 실행 폴더: `predictions.jsonl`, `scores.jsonl`, `report.md`, `manifest.json`(git, 모델, seed, 프롬프트, 임베딩, GT/Corpus 해시, 비용)
- 기타 명령: `make retrieval`(검색 지표만, 0원), `make calibrate`(Judge 대 사람 κ), 실험 플래그는 `uv run python -m eval.run --help`

```
[수집]   law.go.kr OPEN API → 법령 XML(현행 + 시행예정), 판례 XML 400건
[인제스트] make ingest - 규칙 기반, LLM 없음
   ├ parse      법령 XML의 조, 항, 호, 목 태그 → 조문 레코드 (원문 대비 텍스트 누락 0)
   ├ provision  조문 관계 그래프: 위임(법↔시행령↔시행규칙), 같은 법 인용(예외, 준용), 조문→판례(참조조문)
   │            + 시행 상태(시행예정 버전 diff, 부칙 유효기간)
   └ index      조 1개 = 벡터 1개 (Qwen3-Embedding-4B) → FAISS
[질의]   POST /v1/query (JSON, SSE)
   ① 조문 검색 상위 10   ② 1위 유사도 < 0.50 → 거절
   ③ 위임 조문 최대 3개 추가   ④ 연결 판례 중 질문 유사도 ≥ 0.54 상위 2건 추가
   ⑤ 블록마다 시행 상태 표시   ⑥ Luna 생성([S#] 인용)   ⑦ 인용 검증 → 응답
[평가]   Gold Set 100문항 → 질의 경로 그대로 실행 → 규칙 지표 + 공식 채점(Opus ∧ Codex) → report
```

## Part A: RAG 서비스 - 필수 6개, 기대 3개 충족

| 요구사항 | 구현 | 위치 |
|---|---|---|
| Ingest Pipeline | 법령 XML 파싱 → 관계 그래프 → 색인, `make ingest` | `app/ingest/`, `app/index.py` |
| Chunking 전략과 근거 | **조 전체 = 1청크** - 항 분할 시 단서, 나머지 조각 유실(g021)을 실험으로 확인 후 변경, 고정 길이 분할은 인용 정밀도 0.700 → 0.306으로 기각 | Part A 리포트 |
| Embedding, Index | Qwen3-Embedding-4B + FAISS, 판례 인덱스, 관계 그래프 | `data/index/`, `data/processed/` |
| 검색, 생성 API | FastAPI `POST /v1/query` | `app/api.py`, `app/rag.py` |
| Citation | `[S#]` → 조문, 판례 구분, 인용 문장, 시행 상태, 법제처 원문 링크 | `app/rag.py` |
| Request/Response Schema | 요청 `question`, `top_k`(10), `as_of`, `stream`, `precedents` / 응답 `status`, `answer`, `citations[]`, `retrieval[]`, `meta` | `app/schemas.py` |
| (기대) 답 없을 때 응답 불가 | 유사도 게이트 + 모델 `[정보 부족]` + 유효 인용 없으면 거절 → 범위 밖 8문항 거절 1.000 | `app/rag.py` |
| (기대) API Key 환경 변수 | `.env`(git 제외), 전체 커밋 이력 비밀 정보 검사 | `.env.example` |
| (가산) Streaming | SSE `delta` → `final` | `app/api.py` |

## Part C: 개선 실험 - 채택 4개, 효과 없음 확인 다수, 평가 체계 결함 3건 수정

### 전체 결과 (3회 평균, 사전 등록)

| 실험 | 가설 | 결과 | 판정 |
|---|---|---|---|
| 조 전체 색인 | 조를 쪼개면 단서, 나머지 조각 유실 | 분할 조문 질문 순위 상승, 검색 성능 동일 | 채택 |
| **판례 연결** | 조문만으로 결론 안 나는 질문에 판례 주입 시 판례형 상승 | 판례형 완전 정답 0 → 0.444 (CI +0.11~+0.78) | **채택** |
| **임베딩 교체** (KURE → Qwen3-4B) | 검색 누락 감소 | 정답 조문 전부 검색 0.696 → 0.772, 시점형 유의 개선 | **채택** |
| **검색 5 → 10** | 6~10위 정답 조문 회수 | 전체 정답률(Luna) 0.847 → 0.930 (CI +3.7~+13.7%p) | **채택** |
| 시행 상태 표시 끄기 | 시점형 하락(설계 검증) | 시점형 완전 정답 0.667 → 0.240 | 예측 적중 |
| 임베딩 파인튜닝 | 노동법 질의 적응 | 시드 흔들림 이하, 데이터 보강 상승은 **GT 근거 조문 누수**로 판명 | 효과 없음 |
| 일반화 개선 7종 A/B | 유형별 실패 감소 | 유의 개선 0, 재정렬, 질문 재작성은 유의 악화 | 효과 없음 |
| 시점 답변 규칙 | 시행 예정 개정 질문에 쓸 순서 지시 | 시점형 6.3 → 11.0 (CI +6.7~+55.6%p), 전체는 상쇄 | 시점형만 유의 |

### 대표 실험: 판례 연결

- **Hypothesis**: 조문만으로 결론이 나지 않는 질문(L5b)에서 시스템이 "판단 불가"로 끝남 → 검색된 조문에 참조조문으로 연결된 판례를 주입하고 판례임을 밝혀 인용하면 판례형 완전 정답 상승, 부작용으로 인용 정밀도 하락, 입력 토큰 증가 예측
- **Result**

| 지표 | 기준선 | 판례 연결 | 95% CI | 판정 |
|---|---|---|---|---|
| 판례형 완전 정답 (9) | 0.000 | **0.444** | +0.111 ~ +0.778 | 개선 |
| 과잉 거절 | 0.105 | 0.065 | - | 개선 |
| 인용 정밀도 | 0.700 | 0.609 | 유의 | 악화(예측대로) |
| 입력 토큰/호출 | 3,576 | 5,581 | - | +56% |

- **Analysis**: 해결 4문항은 "조문 → 대법원 판단 → 사안별 단서" 형식으로 답변, 미해결 5문항은 실패 지점이 모두 다름(판례 연결 범위, 거절 게이트, 검색 2, 생성) → 단계별 개선 과제로 직결, 인용 정밀도 하락은 잘못된 근거보다 보조 근거 증가
- **Next Steps**: 판례 관련도 재정렬, 판례 직접 검색 보조 경로, 판례 인용형 답변의 사람 판정 표본 - 이후 검색 10, 임베딩 교체로 l5b03, l5b05, l5b08 해결

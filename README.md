# 노동법령 RAG QA + 자체 Eval Harness

노동 관계 법령 24건과 대법원 판례 400건을 근거로 답하는 Citation 기반 RAG 서비스와, 그 품질을 측정하는 자체 평가 체계

> 설계 문서: [docs/design.md](docs/design.md) · 실측 기록: [docs/findings/](docs/findings/) · 실험 사전 등록: [docs/plans/](docs/plans/)

## 요약

- **품질 정의**: **전체 정답률** = 100문항 중 올바르게 처리한 비율 — 답할 수 있는 문항은 정답 포인트를 빠짐없이 담은 답변(완전 정답), 답할 수 없는 문항은 거절 또는 "근거 없음" 명시. 보조로 검색 적중·근거 인용·시점 정확성·근거 없는 주장
- **측정**: Gold Set 100문항(전 문항 사람 확인) · 결정적 지표(검색·거절·인용) + LLM Judge(정답 포인트) · **공식 채점 = Opus·Codex 둘 다 정답일 때만 정답**(생성 모델 Luna의 자기 채점 관대 편향을 3채점자 비교로 확인해 제외, 최종 구성의 정답 포인트 231개 전부 사람 판정과 대조 → Codex 231/231·Opus 204/231·Luna 176/231 일치)
- **증명 방식**: 동일 설정 3회 반복으로 노이즈 폭 측정 → 문항별 3회 평균끼리 비교, 노이즈 폭 초과 **그리고** 문항 대응 부트스트랩 95% CI가 0 제외일 때만 개선·악화 판정, 측정 전 가설 사전 등록
- **결과** (GT v2.2, 3회 평균)
  - **공식 전체 정답률(Opus ∧ Codex)**: 기준선 **0.470** → 최종 구성 **0.633** (+16.3%p, 95% CI +8.7~+24.0, 유의) — Opus 단독 0.610 → 0.770, Codex 단독 0.470 → 0.637
  - 최종 구성 = 조 전체 색인 + 판례 연결 + **Qwen3-Embedding-4B** + **검색 10개**
  - 구성별 기여(Luna 채점 기준, 같은 채점자끼리 비교): 기준선 0.717 → 조 전체 색인 + 판례 연결 0.787 → 임베딩 Qwen3-4B 0.847 → 검색 10개 **0.930**
  - 효과 없음으로 확인한 시도: 임베딩 파인튜닝(KURE 전체 학습·Qwen3 LoRA, v3 데이터 상승은 GT 근거 조문 누수로 판명), 일반화 개선 7종 A/B(유의 개선 0, 재정렬·질문 재작성은 유의 악화)
  - 평가 체계 개선: 1차(61문항)에서 판정 불가였던 실험 대상 유형을 GT 확충으로 판정 가능하게 전환, 단일 기준선의 평균 회귀(가짜 개선) 발견 → 3회 평균 기준선, 채점자 관대 편향 발견 → Luna 채점 제외
- **비용**: 엘리스 크레딧 약 35,000원(5만원 중) — Luna 평가 실행 합계 약 26,800원 + 학습 데이터 생성 약 1,000원 + GPU A100 약 2시간 55분 약 7,300원, 임베딩 추론은 로컬, Opus·Codex 채점은 로컬 CLI 구독

## Corpus: 노동 관계 법령 24건 + 대법원 판례 400건

- 법령: 근로기준법·최저임금법·근로자퇴직급여 보장법·남녀고용평등법·기간제법·파견법·근로자참여법·임금채권보장법 × (법률·시행령·시행규칙), 조문 894개, 본문 약 255페이지
- 판례: 코퍼스 8개 법률 관련 2010년 이후 대법원 판례 400건(판시사항·판결요지), 참조조문 파싱으로 347건이 조문 150개에 연결
- 출처: 국가법령정보 공동활용 OPEN API(`target=eflaw`, `prec`) 현행본 + 시행예정 버전 11개, 원문 XML 스냅샷을 저장소에 포함(법령·판결은 저작권법 제7조 비보호 저작물)
- 선정 이유
  - 정답이 수치·조건·예외로 결정되어 판정 가능: 조문 문장과 대조해 채점
  - 위임 구조(법 → 시행령 → 시행규칙)와 조문 간 참조로 다중 근거 추론 질의가 자연스럽게 발생
  - **최근 개정으로 모델 사전 지식과 현행 조문이 어긋남** → Hallucination 관측 가능. 문맥 없이 질의(closed-book) 시 오래된 사실 100%, 최근 개정 사실 40% 정답(`docs/findings/2026-10-01-closed-book.md`)
  - 공식 현행본에도 효력을 잃은 조항(근로기준법 제16조, 제53조③⑥)과 시행 전 개정이 섞여 있어, 시점 판단이 필요한 실제 난제 포함
  - 조문만으로 결론이 나지 않고 판례가 결론을 정하는 질문(통상임금, 연차 발생 시점 등)이 실무에서 흔함 → 판례 연결 필요

## 시스템 아키텍처

```
[수집]  law.go.kr OPEN API ──► data/raw/laws/*.xml (현행 + 시행예정) · data/raw/precedents/*.xml (판례 400건)
   │
[인제스트]  make ingest — LLM 호출 없음, 규칙 기반
   ├ parse      법령 XML → 조·항·호 구조 레코드 (app/ingest/parse.py)
   ├ provision  Provision Graph (data/processed/provision_graph.json)
   │             ├ 시행 상태: 시행예정 버전 diff + 부칙 유효기간 → 조문별 시행 중·개정 예정·효력 상실
   │             ├ 위임 연결: 법 ↔ 시행령 ↔ 시행규칙 ("법 제N조" 인용)
   │             ├ 같은 법 안 참조: 예외("에도 불구하고")·준용
   │             └ 조문 → 판례: 판례 참조조문 파싱
   ├ index      임베딩 → FAISS IndexFlatIP
   │             ├ whole@Qwen3-Embedding-4B  조 1개 = 벡터 1개, Qwen3-Embedding-4B (기본)
   │             ├ whole     같은 조 단위, KURE-v1 (비교용)
   │             ├ article   512토큰 초과 조를 항·호 경계에서 분할 (비교용)
   │             ├ fixed     고정 길이 512토큰 (비교용)
   │             └ precedent 판례 판시사항+판결요지, KURE-v1 (연결 판례 정렬용, 검색 대상 아님)
   │
[질의]  POST /v1/query (FastAPI, JSON·SSE)
   ① 조문 검색 top-10
   ② 거절 게이트: 1위 점수 < τ 0.50 → [정보 부족]
   ③ 위임 확장: 검색된 조의 시행령·상위법 최대 3개
   ④ 판례 확장: 검색된 조에 연결된 판례 → 질의 유사도 ≥ 0.54 상위 2건
   ⑤ 블록마다 시행 상태 헤더 주입 ("2026-12-08 시행 예정" 등)
   ⑥ GPT-5.6 Luna 생성 ([S#] 인용, 조문 → 대법원 판단 → 사안별 차이 단서)
   ⑦ 인용 검증 → 응답 (인용마다 조문/판례 구분·시행 상태·원문 링크)
   │
[평가]  make eval
   Gold Set 100문항 ─► 질의 경로 그대로 실행 ─► 결정적 지표(M1~M3) + Luna Judge(참고용)
   ─► report.md · scores.jsonl · manifest.json (모델·seed·프롬프트·Corpus·GT 해시·비용)
   eval.rejudge ─► Opus·Codex 정답 포인트 채점 ─► 공식 전체 정답률 (Opus ∧ Codex)
```

## 실행 방법

### 1. 설치

```bash
uv sync
cp .env.example .env   # LAW_OC, ELICE_API_KEY, ELICE_BASE_URL, LLM_MODEL
```

- 요구 사항: Python 3.12+, [uv](https://docs.astral.sh/uv/), 메모리 16GB 이상 권장(Qwen3-Embedding-4B bf16 약 8GB), 공식 채점에는 `claude`·`codex` CLI 로그인 필요
- 기기: CUDA → Apple MPS → CPU 순으로 자동 선택, MPS 기준 질의 임베딩 약 3초(KURE는 0.1초 미만)

| 환경 변수 | 용도 |
|---|---|
| `LAW_OC` | 국가법령정보 공동활용 OPEN API 인증키 (수집 시에만, [open.law.go.kr](https://open.law.go.kr) 활용신청) |
| `ELICE_API_KEY` | 엘리스 ML API Serverless 키 |
| `ELICE_BASE_URL` | `https://mlapi.run/v1` |
| `LLM_MODEL` | `openai/gpt-5.6-luna` |

### 2. Corpus 수집 (선택 — 스냅샷이 `data/raw/`에 포함됨)

```bash
uv run python scripts/fetch_laws.py                        # 법령 현행 + 시행예정 버전
uv run python scripts/fetch_precedents.py bulk --max 400   # 코퍼스 법률별 대법원 판례 일괄 수집
```

### 3. 인제스트

```bash
make ingest      # Provision Graph + 인덱스 5종 (whole@Qwen3-Embedding-4B·whole·article·fixed·precedent), 첫 실행 시 임베딩 모델(KURE·Qwen3-4B) 내려받기
uv run pytest -q
```

### 4. 서버 실행

```bash
uv run uvicorn app.api:app --port 8000
curl localhost:8000/v1/query -H 'Content-Type: application/json' \
  -d '{"question": "연차휴가를 시간 단위로 쓸 수 있나요?", "as_of": "2026-10-01"}'
# 스트리밍: "stream": true → SSE `delta` 이벤트 후 `final` 이벤트(전체 응답)
```

### 5. 평가 실행

```bash
make eval NAME=final                                          # 기본(최종) 구성으로 Gold Set 100문항 → runs/<시각>_final/report.md
uv run python -m eval.rejudge final runs/<실행1> runs/<실행2> runs/<실행3> --all   # 공식 채점(Opus ∧ Codex), 채점마다 캐시 저장·중단 시 이어서
uv run python -m eval.multirun 'runs/*_final*' 'runs/*_exp-r[123]'               # 3회 대 3회 비교(문항별 평균, 부트스트랩 CI)
make eval NAME=legacy ARGS="--strategy article --k 5 --no-siblings --no-precedents"   # 2차 실험 기준선 구성
make eval NAME=h4-off ARGS="--strategy article --no-precedents --no-inject"     # 실험 플래그 예
make eval NAME=noise-2 ARGS="--no-cache"                      # 노이즈 측정: 캐시 없이 재실행
make retrieval ARGS="--strategy article"                      # 검색 지표만(LLM 호출 없음)
make compare ARGS="diff eval/results/v2/baseline-v2 runs/<실행> --base-runs eval/results/v2/noise-v2-2 eval/results/v2/noise-v2-3"   # 전체·유형별·dev/test 판정, 기준선은 3회 평균
uv run python -m eval.mde --gold eval/gold/gold_v2.jsonl runs/a runs/b runs/c   # 유형별 최소 검출 효과
make calibrate                                                # Judge vs 사람 판정 일치도(κ)
```

- 실험 플래그: `--strategy whole@Qwen3-Embedding-4B|whole|article|fixed` · `--k` · `--tau` · `--no-inject` · `--no-links` · `--[no-]siblings` · `--reverse-refs` · `--prompt` · `--[no-]precedents` · `--hybrid` · 일반화 A/B: `--checklist` · `--pending-detail` · `--verify` · `--self-consistency N` · `--query-rewrite` · `--rerank` · `--precedent-search`
- 실행 폴더: `predictions.jsonl`(답변·인용·검색 결과), `judgments.jsonl`(Judge 판정), `scores.jsonl`(문항별 지표), `report.md`, `manifest.json`(git·모델·seed·프롬프트·Corpus·GT 해시·비용)
- 재현성: seed 42·temperature 0 고정, LLM 응답 캐시(`data/cache/llm`, 동일 요청 0원), 실행당 예산 상한(`--budget`)
- 보관 결과: `eval/results/v2/`(2차 이후, GT v2.2), `eval/results/baseline_v1_1`·`exp_*`(1차, GT v1.1), 공식 채점 `eval/results/rejudge_*-official.json`, A/B `eval/results/ab_generalization.json`

## 평가 지표와 한계

양성(Positive) 정의: 거절 지표는 "거절", 검색·인용 지표는 "정답 근거 조문", Judge 지표는 "정답 포인트를 말함"

| 지표 | 무엇을 | 계산 대상 (분모) | 방식 | 기준선 → 최종 | 노이즈 폭 | 한계·맹점 |
|---|---|---|---|---|---|---|
